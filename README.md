# Product Management System API

> **Building and Deploying a Product Management System with User Authentication and Authorization on the Render Cloud Platform, Using Node.js, Express.js, and PostgreSQL (Supabase).**

---

## 1. Project Overview

The **Product Management System** is an enterprise-ready RESTful backend built with Node.js and Express.js, connected to a cloud-hosted PostgreSQL database on Supabase, and designed for zero-downtime deployment on the Render Web Service platform.

The system features robust authentication and Role-Based Access Control (RBAC) across three distinct user tiers: `admin`, `manager`, and `user`. Passwords are encrypted with bcrypt, sessions are authenticated via JSON Web Tokens (JWT), and all input is validated and sanitized to protect against SQL injection, brute force attacks, and common web vulnerabilities.

---

## 2. Technology Stack & Architecture

- **Runtime & Framework**: Node.js (>= 18), Express.js (v4.21)
- **Database**: PostgreSQL (hosted on Supabase)
- **Database Client**: `pg` (node-postgres connection pooling with automatic SSL detection)
- **Security & Middlewares**:
  - `bcrypt` for one-way salted password hashing (10 rounds)
  - `jsonwebtoken` for stateless token signing and verification
  - `helmet` for HTTP security response headers
  - `cors` with configurable origin white-listing
  - `express-rate-limit` for DDoS / brute-force authentication protection
  - `express-validator` for schema validation and input sanitization
- **Testing**: Jest and Supertest
- **Cloud Deployment**: Render Web Service

## 3. Database Schema

The database aligns with `001_initial_product_management.sql` using PostgreSQL `BIGINT GENERATED BY DEFAULT AS IDENTITY`:

1. **`roles`**: `id`, `name` (`admin` | `manager` | `user`), `description`, `created_at`
2. **`users`**: `id`, `name`, `email` (unique), `password_hash`, `role_id` (FK -> `roles.id`), `created_at`, `updated_at`
3. **`categories`**: `id`, `name` (unique), `description`, `created_at`
4. **`products`**: `id`, `name`, `description`, `price` (nonnegative numeric), `image_url`, `category_id` (FK -> `categories.id`), `created_by` (FK -> `users.id`), `created_at`, `updated_at`

## 5. Environment Variables Configuration

Copy `.env.example` to `.env`:

```bash
cp .env.example .env
```

| Variable | Description | Example / Default |
|---|---|---|
| `PORT` | Local HTTP port | `3000` |
| `NODE_ENV` | Environment state | `development` or `production` |
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://postgres.[REF]:[PASS]@aws-0-[REGION].pooler.supabase.com:6543/postgres?sslmode=require` |
| `JWT_SECRET` | Secret key for signing JWT tokens | Random string >= 32 characters |
| `JWT_EXPIRES_IN` | JWT expiration duration | `1h`, `24h`, or `7d` |
| `RATE_LIMIT_WINDOW_MS` | Rate limiting window in milliseconds | `900000` (15 mins) |
| `AUTH_RATE_LIMIT_MAX` | Max auth attempts per window | `20` |
| `CORS_ORIGIN` | Allowed CORS origins | `*` or `https://myfrontend.com` |

## 6. Supabase Setup & Migrations

### Option A: Using the Supabase Dashboard SQL Editor (Recommended)
1. Open your Supabase project at [https://supabase.com](https://supabase.com).
2. Navigate to **SQL Editor** in the left sidebar.
3. Click **New Query**, paste the contents of `001_initial_product_management.sql`.
4. Click **Run**.
5. Verify created tables under **Table Editor** (`roles`, `users`, `categories`, `products`).

### Option B: Running Migrations via CLI
Once you have populated `DATABASE_URL` in `.env`:
```bash
npm run migrate
```
To load sample development categories and demo accounts:
```bash
npm run seed
```

## 9. Render Deployment Instructions

### Method 1: Using render.yaml (Blueprint)
1. Push this repository to GitHub or GitLab.
2. In the [Render Dashboard](https://dashboard.render.com), click **New +** -> **Blueprint**.
3. Select your repository. Render will automatically detect `render.yaml`.
4. Supply your `DATABASE_URL` (Supabase connection string) in the environment prompt.
5. Click **Apply**.

### Method 2: Manual Web Service Setup
1. In Render Dashboard, click **New +** -> **Web Service**.
2. Connect your Git repository.
3. Configure the following parameters:
   - **Name**: `product-management-api`
   - **Environment**: `Node`
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Health Check Path**: `/health`
4. In the **Environment Variables** tab, add:
   - `NODE_ENV`: `production`
   - `DATABASE_URL`: `[Your Supabase PostgreSQL Connection URI with sslmode=require]`
   - `JWT_SECRET`: `[Generate a secure 32+ character random secret]`
   - `JWT_EXPIRES_IN`: `1h`
   - `CORS_ORIGIN`: `*` (or your client frontend URL)
5. Click **Deploy Web Service**.
